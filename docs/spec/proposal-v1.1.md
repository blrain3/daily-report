# 智能日报生成器

## 1. 背景与目标

### 1.1 背景
团队每天需要花 15-30 分钟手写日报，内容包括当天的代码提交、任务进展和协作沟通。这个过程重复、低效，且经常因为遗忘而不完整。团队 Leader 需要了解每个人的工作进展，但手写日报的信息密度低、格式不统一，阅读体验差。

### 1.2 目标
构建一个自动化工具，从团队现有的协作平台中收集当天的工作数据，自动生成结构化的日报，并推送给相关人员。

### 1.3 目标用户
- **主要用户**：5-15 人的研发团队成员（日报的数据来源）
- **主要读者**：团队 Leader / 项目经理（日报的消费者）

## 2. 功能范围

### 2.1 做什么（本期）

#### 2.1.1 成员配置
系统以仓库根目录的 `members.yaml` 为成员唯一来源，启动时加载并校验。字段如下：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 日报中显示的姓名，全局唯一 |
| `github` | 是 | GitHub 用户名，全局唯一，用于匹配 commit 作者 |
| `feishu_open_id` | 否 | 飞书 open_id，用于匹配任务负责人与群消息发送人 |
| `email` | 是 | 收件地址（Leader 汇总邮件另配，见 2.1.5） |

校验规则：`github` 或 `name` 重复时，程序启动即失败并打印重复项所在行号；缺失 `feishu_open_id` 的成员仍参与代码提交部分，日报中标注「无飞书绑定」；文件不存在或 YAML 解析失败时启动失败，不进入采集阶段。

#### 2.1.2 数据采集

- **代码提交**：通过 GitHub REST API 获取 `members.yaml` 中各 `github` 用户在配置仓库内、采集窗口内的提交，字段为 `sha`、`message` 首行、`author`、`committed_at`、`additions`/`deletions`。
- **任务进展**：通过飞书开放平台任务接口，获取采集窗口内状态变更为「新建 / 进行中 / 已完成」的任务，字段为任务标题、负责人、变更前后状态、变更时间。
- **协作沟通**：从飞书群消息按**关键词表**匹配，命中后按发送人聚合，输出**原文片段**——保留发言时间、发送人、正文前 80 字，不做概括、改写或归类。关键词表默认 `日报`、`bug`、`上线`、`发布`、项目名，可由配置覆盖。

#### 2.1.3 采集窗口

**定义：采集窗口 = 上一工作日 00:00 至本次执行时刻。**

异常与边界规则：

- 上周五至本周一之间执行时，窗口自然覆盖周末，不因跨天截断。
- 若上一工作日执行失败（无成功记录），窗口回溯至最后一次成功执行的时刻，最长回溯 72 小时；超出部分在日报对应段落标注「窗口已截断，更早记录未包含」。
- 每次执行成功后写入一条执行记录（见 2.1.6），用作下次窗口计算的依据。

#### 2.1.4 日报生成
- 将采集到的数据按「代码提交 → 任务进展 → 协作沟通」三部分组织，每位成员一段。
- 成员当天无任何记录时，该段输出「今日无记录」，不省略该成员。
- 输出格式为 Markdown，同时可渲染为 HTML 邮件正文。

#### 2.1.5 推送通知
- 每个**工作日** 18:00 触发（触发与节假日的判定见 2.2）。
- 通过 SMTP 向 Leader 发送 HTML 格式日报；Leader 收件地址独立配置，不占用成员 `email`。
- 通过飞书机器人把 Markdown 日报发到指定群。
- 推送失败时保留已生成的日报文件，退出码非 0，便于 cron 侧告警。

#### 2.1.6 运行记录与日报存储
本地 SQLite 保存两类数据：`run`（每次执行的时间、窗口起止、各数据源成功与否）与 `daily_report`（按 `(date, member)` 唯一）。重跑同一天时更新既有记录而非新增，避免重复推送与重复留档。

### 2.2 节假日与触发规则

cron 每日 18:00 触发一次，**是否真正执行由程序读取 `holidays.yaml` 判定**，而不是靠 crontab 的星期字段——否则中国调休会把「非工作日不触发」变成假通过。

`holidays.yaml` 每年初维护，结构：

```yaml
year: 2027
holidays:            # 法定节假日，不生成日报
  - date: 2027-01-01
    name: 元旦
workdays:            # 调休上班日，即使是周末也生成日报
  - date: 2027-02-06
    name: 春节调休
```

节假日日期以国务院办公厅当年通知为准，由维护者手工填写；文件缺失或未覆盖当年时，程序**按周一至周五工作日执行**，并在日报页脚标注「节假日表未覆盖，已按默认工作日判断」。

### 2.3 不做什么（本期明确排除）
- **不做**智能摘要和 AI 总结（只做关键词匹配与原文摘录，不做语义理解、不调用大模型）
- **不做**移动端 App
- **不做**历史日报的搜索、统计与可视化（存储仅用于去重与补发，不提供查询界面）
- **不做**个人日报的编辑和补充功能
- **不做**多团队 / 多租户支持

### 2.4 技术约束
- 后端语言：Python 3.11+
- 部署环境：公司内网服务器（Docker 容器）
- 外部依赖：GitHub REST API、飞书开放平台 API、SMTP
- 运行方式：cron 每日触发一次，无常驻服务
- 数据存储：本地 SQLite（`run` 与 `daily_report` 两张表）
- 配置：`members.yaml`、`holidays.yaml`、`config.yaml`（关键词表、仓库列表、SMTP 与飞书凭据引用）

### 2.5 超时与重试预算

为避免「限流重试」与性能目标互相拆台，约束如下：

- 每个数据源（GitHub / 飞书任务 / 飞书消息）独立超时 15 秒，三路并发执行。
- 单个数据源重试最多 3 次，重试总等待不超过 20 秒（指数退避 2/4/8 秒但受总预算封顶）。
- 整体耗时超过 45 秒时放弃剩余重试，用已获取部分出报；未获取的数据源在该段标注「数据获取失败：<原因>」，不静默跳过。

## 3. 验收标准

### 3.1 成员配置
- [ ] `members.yaml` 缺 `name` 或 `github` 时，程序启动失败并指出行号
- [ ] 两个成员 `github` 重复时，启动失败并指出重复项
- [ ] 成员缺 `feishu_open_id` 时正常出报，该成员段落标注「无飞书绑定」
- [ ] `members.yaml` 不存在时，程序以非 0 退出码结束且不产生任何输出文件

### 3.2 数据采集
- [ ] 能获取配置仓库内、采集窗口内全部成员的 commit 记录（不只作者为成员的提交）
- [ ] 能获取采集窗口内状态发生变更的飞书任务
- [ ] 能从飞书群消息中按关键词表匹配记录，输出原文片段；命中消息数与日报中出现的片段数一致
- [ ] 三个数据源之一超时或报错时，其余数据源结果照常入报，失败项标注「数据获取失败」

### 3.3 采集窗口
- [ ] 周一执行时，窗口从上周五 00:00 起算，周末提交不丢失
- [ ] 上次执行失败后重跑，窗口回溯至最后成功执行时刻，最长 72 小时
- [ ] 回溯超过 72 小时时，日报标注「窗口已截断」

### 3.4 日报与推送
- [ ] 生成的日报包含三个部分：代码提交、任务进展、协作沟通
- [ ] 当天无记录的成员显示「今日无记录」，不被省略
- [ ] Markdown 格式正确，可直接渲染为可读的 HTML
- [ ] Leader 收到 HTML 格式日报邮件
- [ ] 飞书机器人成功将日报发送到指定群
- [ ] 推送失败时退出码非 0，且已生成的日报文件保留

### 3.5 存储与去重
- [ ] 同一 `(date, member)` 重跑两次，`daily_report` 中只有一条记录
- [ ] `run` 表可查到每次执行的时间、窗口起止与各数据源状态

### 3.6 节假日
- [ ] 给定节假日表，法定节假日不生成、不推送日报
- [ ] 调休上班的周六正常生成并推送
- [ ] 未配置当年节假日表时，按周一至周五执行并在页脚标注

### 3.7 性能与稳定性
- [ ] 单次日报生成（5 人团队）耗时 < 60 秒
- [ ] 人为注入 GitHub 限流（429）后，重试不超过 3 次，整体仍在 60 秒内完成或按 2.5 降级出报
- [ ] 飞书 token 过期时自动刷新一次并重试，刷新失败则按数据源失败处理

## 4. 术语定义

| 术语 | 定义 |
|------|------|
| 日报 | 系统自动生成的每日工作总结，包含代码、任务、沟通三部分 |
| 成员 | 在 `members.yaml` 中登记、具备 GitHub 用户名的工作者 |
| 数据源 | 提供工作数据的外部平台（GitHub、飞书任务、飞书消息） |
| 采集窗口 | 上一工作日 00:00 至本次执行时刻；异常时按 2.1.3 回溯 |
| 原文片段 | 群消息命中关键词后的原始文本摘录，含时间、发送人与正文前 80 字，不作改写 |
| 工作日 | `holidays.yaml` 判定为工作的日期；未覆盖当年时退化为周一至周五 |

## 5. 配置文件示例

`members.yaml`：

```yaml
members:
  - name: 张三
    github: zhangsan
    feishu_open_id: ou_xxxxxxxxxxxxxxxx
    email: zhangsan@example.com
  - name: 张三
    github: zhangsan
    email: zhangsan@example.com      # 未填 feishu_open_id，日报标注「无飞书绑定」
```

`holidays.yaml` 与 `config.yaml` 的结构见 2.2 与 2.4；实际日期与凭据在部署时填写，不入库、不进版本控制。
